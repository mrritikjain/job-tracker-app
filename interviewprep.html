Job Tracker

Interview Preparation Guide

1. Project Overview & Elevator Pitch

The Problem

Job hunting is chaotic. Applicants often lose track of which companies they've applied to, their statuses, and follow-up dates.

The Solution

A centralized dashboard to register, log applications, track status (Applied, Interview, Rejected), and visualize progress.

Quick Summary for Interviewers

"I built a vanilla JavaScript Single Page Application-style (SPA) project that serves as a personal CRM for job seekers. It features a custom authentication system, a dynamic dashboard with CRUD capabilities, and real-time filtering. I built it without frameworks to demonstrate my solid grasp of DOM manipulation and LocalStorage."

2. Tech Stack

  • HTML5 Semantic Structure
  • CSS3 Custom Properties, Flexbox/Grid
  • JavaScript ES6+, LocalStorage, FileReader API

Why Vanilla JS?

To master the core mechanics of the web—DOM manipulation, event bubbling, and state management—before abstracting them with libraries like React.

Why LocalStorage?

It provides a lightweight, client-side persistence solution, keeping user data active across sessions efficiently for a solo project.

3. Implementation Deep Dive

A. Authentication (`usersign.js`)

Session Token: localStorage.setItem("currentUser", email) acts as the active session.

Duplication Check: Uses Array.prototype.find() to prevent re-registering emails.

B. The Dashboard (`dashboard.js`)

1. Authorization Gatekeeping

const currentUserEmail = localStorage.getItem("currentUser");
if (!currentUserEmail) { 
    window.location.href = "usersign.html"; 
}

Immediately protects the route if no user is logged in.

2. Image Handling (FileReader)

Using readAsDataURL to convert images to Base64 strings for storage in JSON.

3. Search Optimization (Debounce)

let debounceTimer;
searchInput.addEventListener("input", () => {
    clearTimeout(debounceTimer);
    debounceTimer = setTimeout(searchLogic, 300);
});

Prevents the search function from firing on every keystroke, improving performance.

4. Notable Challenges Solved

Multi-User Logic

Challenge: Data leaking between users.
Solution: Strict filtering: jobs.filter(j => j.email === currentUserEmail) ensures users only see their own data.

State Sync

Challenge: Updating UI counts immediately after status changes.
Solution: Helper functions saveJobs() and updateCounts() are called synchronously after every state mutation.

5. Common Questions

  • LocalStorage vs Cookies?
    LocalStorage is persistent and has more capacity (5MB+). Cookies are sent with every server request and are much smaller (4KB).
  • Event Loop?
    Explain how setTimeout pushes the callback to the Task Queue, waiting for the Call Stack to clear.
